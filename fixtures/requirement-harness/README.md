# Requirement harness

One test slot per authored promise in `metaobjects/meta.requirements.yaml`, in every
port. Generated by `scripts/generate-requirement-harness.ts`; **do not edit in place**
— a regeneration overwrites the file whole.

## What it is for

`fixtures/registry-conformance/expected-registry.json` proves the five ports **spell**
the vocabulary identically. It is blind to what they **do** with it, and the blindness
is measured rather than feared: one attribute naming a column was found meaning three
different things across the ports at once, while every port byte-matched the manifest
throughout.

The ledger states what each piece of vocabulary must do. This turns each of those
statements into a **named slot** in every port, so a promise nobody checks is visible
as a slot nobody filled — instead of invisible as a sentence nobody wrote.

The population is the ledger's **L4 (one per concrete subtype)** and **L5 (per
promise-bearing attribute)** entries. L1–L3 are organisational and have nothing to
assert at the grain of a test.

## Every slot is skipped, and that is a decision

The shipped `requirementTests()` renderer **fails** a live stub deliberately: for an
adopter, an empty green test asserts the opposite of the claim. That rule is right
there and wrong here, and the difference is worth stating rather than departing from
quietly.

An adopter generates a handful of stubs for capabilities nothing else checks. This
generates 109 across five ports for a library whose conformance corpora already check
a great many of them. Emitting 545 red tests would claim nothing is verified, which is
false — and a suite red for a false reason gets silenced wholesale, taking with it the
slots that were telling the truth.

So the stubs are skipped and **the drift gate is what has teeth**: the generated set
must match the ledger exactly, so a new promise appears as a new unfilled slot in all
five ports and cannot be quietly forgotten.

## What is wired, and what is not

| Port | Generated | Runs in CI |
|---|---|---|
| TypeScript | ✅ | ✅ — the gate executes it, so the shape is proven by a port that runs it |
| Python · Java · Kotlin · C# | ✅ | ❌ — scaffolds only |

The four unwired ports are **not** in any build path, so they compile nothing and
break nothing. Wiring one is that port's adoption work: move the file into its test
tree and add it to that project's build. This table is the honest state rather than an
implied harness that runs everywhere.

## Filling a slot

Move it into the port's own suite and write the assertion the skip reason describes —
one that **fails when the counterexample happens**. Nothing here rewrites a body, so a
slot you have filled must leave this directory, or the next regeneration overwrites it.
