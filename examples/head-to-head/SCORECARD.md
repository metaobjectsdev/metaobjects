# Head-to-head scorecard

> **Self-measured.** The MetaObjects maintainers wrote both setups and this harness. The baseline is built to be a competent do-it-yourself stack, but we chose its tools, its scenarios and its app, and a reader who disagrees with any of those should change them and rerun (`./run.sh`). Read [README.md](README.md) for what this does and does not measure.

Generated by `./run.sh` on 2026-10-31; 7 scenarios × 2 setups took 232 s. Every result cell below is computed from the exit codes of the checks that ran; none is typed by hand.

## Results

Each scenario is one change a developer makes where the setup keeps its source of truth, followed by that setup's own generators. The pull-request gate (for S5, the live-database check) is then run, and each check's exit code is recorded. The **probe** is a happy-path run (create a customer through the API, render its prompt in the worker) that is identical in both setups; it is informational and is not part of either gate. Two different questions follow, scored separately.

### Do the layers stay consistent?

**red** means at least one check other than the partner-contract diff failed: the model, the generated code, the database, the prompt and the hand-written code disagreed and a check said so. **green** means every such check passed. It is not a claim that the change was safe; the probe column says whether the happy path still works.

### What each scenario does

- **S0 Control: no change.** Nothing is edited. Every check must pass, so a red cell elsewhere is not noise from the setup itself.
- **S1 Rename a field.** `Customer.email` becomes `contactEmail` in the place each setup treats as its source of truth, then that setup's own generators run. The prompt payload, the database column and the hand-written code are left as they were.
- **S2 Add a required field.** `Customer` gains a required `country` (2 characters). Generators run; nothing else is touched.
- **S3 Change a prompt variable.** The prompt template is edited to use `{{ fullName }}`, which the payload does not have. Nothing is regenerated.
- **S4 Skip a regen.** An optional `nickname` field is added to the model and no generator is run, so the committed generated files are stale.
- **S5 Edit the database by hand.** Someone runs `ALTER TABLE customers ADD COLUMN vip boolean NOT NULL DEFAULT false` on a live database. The check is each setup's live-database drift command, the one a team runs on a schedule or at deploy time.
- **S6 Change a field on the partner API.** `name` becomes required on `POST /customers`: a request partners send today without it would be rejected. Generators run; the database follows where the setup derives it.
