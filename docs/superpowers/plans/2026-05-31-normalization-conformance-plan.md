# Phase B — Normalization-conformance + Projection Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Per-unit gate (hard):** code-reviewer AND code-simplifier on each unit, fix findings, then merge-forward.

**Goal:** Make every wire-type's canonical normalization (temporal types especially) and every projection aggregate (sum/avg/min/max + passthrough-view read) enforced by the *shared* persistence-conformance round-trip across all 5 ports — replacing divergent per-port normalization unit tests.

**Architecture:** Extend the existing shared corpus entities (`Asset` gets temporal columns; `Week` gets a numeric field; `ProgramStat` gets aggregate fields; add a passthrough-view read scenario). TS is the schema authority: it regenerates `canonical/schema.postgres.sql` (so the headless drift-check covers new columns) and its view-synthesis must emit `sum/avg/min/max` (only `count` exists today). Each port's persistence-conformance runner then reads those columns through its runtime and canonicalizes per `normalization.md`. Gated by the integration suite (all 5 ports, Testcontainers Postgres, runs on all PRs after Phase A).

**Tech Stack:** TS `migrate-ts` (view-ddl-emit, expected-schema) + `integration-tests`; per-port persistence-conformance runners (C# `MetaObjects.IntegrationTests`, Java `integration-tests`, Python `tests/integration`, Kotlin `integration-tests-kotlin`); shared fixtures under `fixtures/persistence-conformance/`.

**Design:** `docs/superpowers/specs/2026-05-31-normalization-conformance-design.md` (`f8f60c93`). **Grounding:** `normalization.md` already pins the temporal canonical rules (TIMESTAMP no-Z / TIMESTAMPTZ UTC-Z / DATE / UUID / JSONB / NUMERIC / float / BYTEA) — only `TIME` is missing. The `@agg` vocabulary is `count|sum|avg|min|max` but only `count` has fixtures (and possibly only `count` is implemented in view-synthesis).

## Cross-cutting contract (every unit must honor)

- **Canonical wire forms** (from `normalization.md`): `TIMESTAMP`→`"YYYY-MM-DDTHH:MM:SS"` (no `Z`); `TIMESTAMPTZ`→`"YYYY-MM-DDTHH:MM:SSZ"` (UTC always); `DATE`→`"YYYY-MM-DD"`; `TIME`→`"HH:MM:SS"` (NEW rule, no fractional component); `UUID`→lowercase; aggregate result types: `sum`/`min`/`max` over an `INTEGER` → JSON **number** (per the INTEGER rule), `avg` → **string** plain-decimal (per the float rule).
- **Whole seconds only** (B scope): every seeded `TIMESTAMP`/`TIMESTAMPTZ`/`TIME` value is whole-second; the canonical form carries NO fractional component. Fractional-second normalization is out of scope for B.
- **TIMESTAMPTZ proof:** the seed uses a **non-UTC offset**; the asserted read is the UTC `Z` form — proving normalization, not just format.
- **No new field subtypes:** `field.timestamp`/`field.date`/`field.time`/`field.int`/`field.long`/`field.double` all already exist.
- **DRY corpus:** scenarios + metadata are authored ONCE (shared fixtures); each port runs them. Per-port work is only the read-path/normalization implementation, never re-authoring fixtures.
