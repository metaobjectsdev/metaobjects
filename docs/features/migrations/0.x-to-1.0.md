# Migrating `0.x` → `1.0` (Metamodel 1.0)

This guide consolidates every breaking change an adopter absorbs moving from the
`0.x` / `7.x` line to the **1.0 stable** release (Metamodel 1.0). Most of these
already shipped incrementally across `0.14`–`0.15`; the 1.0 cut is the moment to be
on all of them. The stability promise that begins at 1.0 is the
[compatibility policy](../../compatibility-policy.md).

## 0. Update the dependency version

Package versions **re-baseline** at the cut (both forward — see
[ADR-0035 §2](../../../spec/decisions/ADR-0035-one-zero-stability-commitment-and-version-unification.md)):

| Ecosystem | From | To |
|---|---|---|
| npm / PyPI / NuGet | `0.15.x` | **`1.0.0`** |
| Maven Central (Java / Kotlin) | `7.7.x` | **`8.0.0`** |

All ports at these versions implement **Metamodel 1.0**. There is no `1.0`–`7.x`
overlap: the lines are independent and each only moves forward.

## 1. `verify` is strict-by-default (shipped 0.14.0)

`verify` now **fails** on unknown types / subtypes / attributes / children across all
CLI ports, rather than silently passing.

- **If the gate now fails on your metadata:** the offending attr/child is not a
  registered metamodel member. Either correct it, or — for genuinely author-supplied
  properties — move it into the registered `attr.properties` bag (exempt from the
  strict-attr check). Errors name the exit: `ERR_UNKNOWN_ATTR` /
  `ERR_CHILD_NOT_ALLOWED` / `ERR_UNKNOWN_TYPE`.
- **Escape hatch** (per port): `meta verify --lax` (TS), `metaobjects verify --lax`
  (Python), `dotnet meta verify --lax` (C#), `-Dmeta.lax=true` (Java/Kotlin Maven).
  `gen`/`docs` stay lax by default; the Java goals gate at generate-time too.

## 2. A jsonb open-bag is a parsed JSON value (shipped 0.14.0)

A `field.string` + `@dbColumnType: jsonb` now surfaces a **parsed JSON value** at the
API boundary (TS `z.unknown()`, Python `Any`, Java/Kotlin/C# the native map/node),
not a JSON string. The stored/wire form is unchanged.

- **Migration:** consumers that received a string and called `JSON.parse(...)` (or the
  per-port equivalent) must drop that parse — the value arrives already parsed.

## 3. `field.timestamp` is instant-by-default (shipped 0.15.0)

`field.timestamp` now maps to an **instant** (`timestamptz` / `Instant` /
`DateTimeOffset` / timezone-aware `datetime`) by default.

- **To keep the old naive/local behavior:** add **`@localTime: true`** to the field.
- **Retired:** `@dbColumnType: timestamp_with_tz` — the timezone-awareness is now
  derived from the subtype, so remove that escape.

```jsonc
// before (0.14):                      // after (1.0):
{ "field.timestamp": {                 { "field.timestamp": {
    "name": "createdAt",                   "name": "createdAt" }}   // instant by default
    "@dbColumnType": "timestamp_with_tz"
}}                                      // ...or naive: add "@localTime": true
```

## 4. `@dbColumnType` slim-and-derive (shipped 0.15.0)

`@dbColumnType` narrows to genuinely-physical escapes. **Array-ness is derived** from
`isArray`, and the `*_array` column types (`uuid_array`, `text_array`) plus `@kind:
text` are **dropped**.

- **Migration:** remove any `@dbColumnType: *_array` / `@kind: text`; use the field
  subtype + `isArray` (arrays derive their column type automatically).

## 5. `index.*` type + `identity.secondary` key-purity (shipped 0.15.1)

`@unique` is **removed** from `identity.secondary` (now inherently a *unique* key →
a legacy `@unique` fails load with `ERR_UNKNOWN_ATTR`). A non-unique index moves to
the new **`index.lookup`** type.

- **Full mechanical rewrite + the no-DDL-churn guarantee:**
  [identity.secondary → index.lookup](identity-secondary-to-index-lookup.md).

## 6. `origin.passthrough` is type-preserving (shipped 0.15.x)

A field carrying `origin.passthrough @from: "Entity.field"` forwards the source value
unchanged, so its declared `field.<subType>` and array-ness must be **identical** to the
resolved source field. A divergence now fails load with `ERR_PASSTHROUGH_TYPE_MISMATCH`
(e.g. a `field.uuid` source surfaced by a projection as `field.string` — the exact
mismodeling that leaves a view `String`-typed over a `uuid` column and forces hand-written
`String↔UUID` coercion). The check compares **subType and array-ness only — nullability is
deliberately not judged** (a view over an outer join legitimately widens `NOT NULL` →
nullable). This generalizes and retires the narrow, stored-proc-parameter-ref-only
`ERR_PARAMETER_REF_PASSTHROUGH_TYPE_MISMATCH` (FR-015) into one host-agnostic invariant
covering projections, entities, values, and parameter refs alike.

- **If load newly fails:** the error names both the declared type and the source type.
  Declare the source's type (usually the fix — the projection was wrong), or set
  `@convert: true` on the `origin.passthrough` if the divergence is intentional.
- **`@convert` is an acknowledgement only — it does NOT generate a cast**; the value flows
  through unchanged and the consumer owns any coercion. Real type-converting projections are
  `origin.computed`'s job (`@expr`, shipped in #195); #159 adds further node kinds to that
  expression grammar.

## 7. Assembly origins leave `object.value`; nested payload targets are value-only; `@role` shrinks (shipped 0.21.0 / Maven 7.21.0)

Three coordinated breaking changes in one cut (#210 / #212):

- A field hosted on an `object.value` may no longer carry an **assembly origin**
  (`origin.aggregate` / `origin.computed` / `origin.collection` / `origin.first` —
  `origin.collection` was itself retired in `0.24.0`, see §8D, so on a current
  release the rule reads as the three survivors)
  — `ERR_SUBTYPE_RULE_VIOLATION`. Re-host the payload as a **sourceless
  `object.projection`**; `@payloadRef`/`@responseRef` now accept one.
  `origin.passthrough` on a value (FR-015 parameter lineage) stays legal.
- A payload field's nested `field.object @objectRef` must resolve to an
  `object.value` (previously unconstrained by the loader; TS/C#/Python accepted
  and emitted from a non-value target) — `ERR_SUBTYPE_RULE_VIOLATION`.
- `source.rdb @role` is exactly `primary | replica`; the former `index` /
  `cache` / `publish` / `mirror` members are retired (reserved-not-registered)
  — `ERR_BAD_ATTR_VALUE`.

- **Full mechanical rewrites for all three:**
  [value-assembly-origins-and-source-role-shrink.md](value-assembly-origins-and-source-role-shrink.md).

## 8. The coordinated breaking batch (shipped `0.24.0` / Maven `7.24.0`)

**Four vocabulary retirements in one release**, batched deliberately: under ADR-0023's sealed
strict registry a retirement has no deprecation shim, so each is a migration you must
perform, and two breaking MINORs back to back would mean two migrations for work budgeted as
one. `metamodelVersion` moved `0.9` → `0.10`, once, covering all four.

Each has its own guide with the exact loader error and a rewrite rule. In rough order of how
likely you are to be affected:

**8A. `@readOnly` → `@mutability`** —
[readonly-to-mutability.md](readonly-to-mutability.md)

`@mutability: readWrite | writeOnce | readOnly` replaces the boolean on every `field.*`
subtype. `@readOnly: true` → `@mutability: "readOnly"`; `@readOnly: false` → delete it
(`readWrite` is the default). The new middle mode is the point: **`writeOnce`** — settable on
create, frozen after — which the boolean could not express, and which an assigned primary key
has always wanted. Measured at **zero uses** across three adopting estates, so this is likely
an empty migration.

**8B. The requirement vocabulary becomes prescriptive-only** —
[verified-by-retirement.md](verified-by-retirement.md)

`@verifiedBy` and `@supersededBy` deregister (`ERR_UNKNOWN_ATTR`); `@status` shrinks to
`planned | live | partial`, so `abandoned` and `superseded` fail `ERR_BAD_ATTR_VALUE`.
Retiring a capability is now DELETION of its requirement. Only affects projects that declare
`requirement.*` nodes at all.

**8C. A template subtype's axis is DIRECTION** —
[template-direction-outbound-vs-inbound.md](template-direction-outbound-vs-inbound.md)

`@promptStyle` on a `template.output` fails the load; the inbound tier (parser, tolerant
extractor, response-format fragment) belongs to a `template.prompt` carrying `@responseRef`,
and emitted paths follow the direction.

**8D. `origin.collection` retires to reserved-not-registered** —
[origin-collection-retirement.md](origin-collection-retirement.md)

Any use now fails `ERR_UNKNOWN_SUBTYPE`. It duplicated `origin.aggregate @agg: collect` on a
smaller attr set and nothing ever dispatched on it, so deleting the child changes no
generated output. A whole-object rollup returns additively with
[#335](https://github.com/metaobjectsdev/metaobjects/issues/335).

## 9. Two forms the loader used to accept (shipped `0.24.1` / Maven `7.24.1`)

Neither of these is a contract change — each is a form that could never work being refused
at last, the category [the compatibility policy](../../compatibility-policy.md) calls
*correcting input we wrongly accepted*. Both are fixed by **deleting an attribute that was
doing nothing**, and `metamodelVersion` moved `0.11` → `0.12` across the pair.

**9A. An index key is `@fields` XOR `@expr`**
([#342](https://github.com/metaobjectsdev/metaobjects/issues/342))

Declaring both on one `identity.secondary` / `index.lookup` now fails `ERR_INVALID_INDEX`.
It used to load and **silently throw half of itself away**, so an expression index was
undeclarable in the one spelling that appeared to work. Delete whichever half you did not
mean; `meta upgrade --apply` repairs this one for you.

**9B. `@filterable` / `@sortable` are refused on an `isArray` field**
([#335](https://github.com/metaobjectsdev/metaobjects/issues/335))

`true` on an array field emitted a `like`/`eq` rule against a `text[]` column — SQL that
cannot execute. Delete the attribute; the endpoint it appeared to enable never worked.

*(`0.24.2` through `0.24.5` are additive. `0.24.2` restores `@status: retired` and
`@supersededBy` — nothing that loads on `0.24.1` stops loading.)*

## 10. The `0.25.0` line (Maven `7.25.0`) — one theme, six migrations

`metamodelVersion` moved `0.13` → `0.14`. The whole line is spent on one defect wearing
different hats: **a name resolved twice by two different mechanisms**, two doors
disagreeing with nothing comparing them. Only 10A is a metadata edit; the rest are code.

**10A. An authored `<type>.base` node no longer loads** —
[base-subtypes-are-not-authorable.md](base-subtypes-are-not-authorable.md)

`ERR_ABSTRACT_SUBTYPE_AUTHORED`, at both the root and child doors, in all five ports.
**This one is the reason to read the list**: TypeScript, C# and Python accepted every such
node before, while Java and Kotlin refused every one — so one document had two verdicts
depending on which toolchain read it. If you author metadata only through the JVM you were
never able to write this; if you author through TS, C# or Python, check for it.

**10B. The API base URL leaves the entity descriptor** —
[api-base-url-leaves-the-entity-descriptor.md](api-base-url-leaves-the-entity-descriptor.md)

`$apiPrefix` was frozen into generated code at `meta gen` time, which made a browser bundle
unbuildable-once-and-servable-against-many-hosts: a dev proxy, a preview environment, a
separate API host and an SSR pass all need a different base. It moves to the runtime
provider, with `baseUrl` optional and defaulting to `""`.

**10C. A TPH subtype's `$path` now names the address that is actually served**

`Car.$path` becomes `/vehicles/car` rather than `/cars`. A TPH subtype emits no routes file
of its own — the hierarchy mounts from the discriminator base at `<base>/<segment>` — so the
old value named an endpoint that **404s**, and the generated TanStack grid hook fetched it.
Unchanged for everything that is not a TPH subtype. Regenerate; every consumer reads the
const.

**10D. `<Entity>Names` mirrors the metadata tree** (all five ports)

**Read this one if you hand-wrote code importing `<Entity>Names`.** `name` still exists and
now holds the OBJECT's name — so `pgTable(CustomerNames.name, …)` still *compiles* and binds
a table called `Customer`. That is the only silently-changed member; everything else that
moved fails to compile. **Grep for `Names.name` before you regenerate.** One key used to hold
a table, a view and a stored procedure, told apart only by a sibling `kind`.

**10E. The `@metaobjectsdev/sdk/agent-docs` subpath is removed**

Breaking only for code importing `AGENT_DOCS_BODY` from it. **Delete the import; the live
surface is `@metaobjectsdev/sdk/agent-context`.** It was the pre-agent-context single-blob
reference — `meta init` had already stopped scaffolding it, but it stayed exported while its
prose rotted, teaching six things the loader rejects. It was deleted rather than corrected,
because keeping it means two prompt surfaces held in agreement forever, one of which nothing
assembles, tests or scaffolds.

**10F. Python `GenConfig.column_naming` raises `TypeError`**

It was read by **nothing** — setting it ran clean, reported success and changed no output, so
a project that believed it had chosen a naming strategy had silently not. It now refuses and
points at the parameter that works: `ObjectManager(..., column_naming=...)`.

**Two more change what `meta gen` emits without breaking a load:**

- **The five `@emit*` attributes are retired** —
  [emit-attrs-to-generator-config.md](emit-attrs-to-generator-config.md). They were never
  registered vocabulary, so the documented opt-out passed `meta gen` and failed
  `meta verify`. Narrow at the GENERATOR instead (`routesFile({ filter })`, and
  `tanstackGrid/GridHook({ tphSubtypeGrids })` for the opt-IN). `meta upgrade --apply`
  removes them — **and an artifact you had suppressed this way will now appear.**
- **Seven attributes codegen read that no provider registers are removed.** Same shape:
  authored, accepted by `meta gen`, rejected by strict `verify`.

## 11. Deprecated `codegen-ts/generators` export removed (at the 1.0 cut)

Importing the built-in generators from `@metaobjectsdev/codegen-ts/generators`
(`entityFile` / `queriesFile` / `routesFile` / `barrel`) is **removed** at 1.0.

- **Migration:** import the owned copies `meta init` scaffolds into
  `codegen/generators/*` and wire those in `metaobjects.config.ts`. See
  [own-your-codegen](../own-your-codegen.md). (If you scaffolded with a recent
  `meta init`, you already import the owned copies — no change needed.)

## Additive in 1.0 (no migration required)

- **`field.uri` / `field.inet` subtypes + `@stringFormat`** (`email` / `hostname`)
  for validated-string content — new, opt-in. Adopt where useful.
- **Reverse navigation** via generated explicit FK finders — additive.
- **`field.enum`, `index.lookup`, currency, M:N relationships** — all available.

## Not in 1.0: the declared-API surface (FR-024)

`api.*` / `operation.*` / `binding.*` are **deferred** post-1.0 (reserved but
unregistered). Nothing to migrate; they can be added later without a breaking change.
Derived CRUD remains the zero-config default. (Tracked in #10.)
